# Portfolio evidence policy

The website should communicate what has **actually been built and verified**, not
illustrative metrics or drafts that could be mistaken for achievements.

## Public repositories to evaluate for featured work

| Repository | Public evidence | Verification still needed |
| --- | --- | --- |
| [QuestPop](https://github.com/Aarish-khatib/Questpop) | Application source, setup instructions, regression tests and GitHub Actions build workflow | Manual interaction, mobile usability, accessibility and current deployment |
| [Universe](https://github.com/Aarish-khatib/Universe) | Source and development README describing the scientific visualization approach | Live demonstration, scientific sources, interaction tests |
| [Limitless AI](https://github.com/Aarish-khatib/AI) | Extensive source tree, feature matrix, setup and validation scripts | Independent release validation and confirmation of each claimed capability |

This list is a review queue, **not** a claim that every feature is production-ready.
ICE-related work and other private repositories must remain private unless the owner
explicitly approves releasing individual details.

## Rules for public claims

1. List a certificate only with a real issuer, date and evidence.
2. Show project counts or user/client numbers only when they can be substantiated.
3. Publish named testimonials only with genuine client permission and evidence.
4. Do not call a concept a completed product; use labels such as *prototype*,
   *work in progress*, or *released* after confirming the status.
5. Do not publish personal contact numbers, school details, location, credentials,
   or private source material without explicit review.
6. Prefer project demos, test links, documented decisions and limitations to
   decorative counters or unverified endorsements.
7. Any AI-assisted edits should be reviewed for factual claims, accessibility,
   performance and security before release.

## Prioritized implementation

- Make the landing page lead with links to verifiable public source projects.
- Review `SHOWCASE_PROJECTS`, `CERTIFICATE_FALLBACKS`, and all Supabase content
  before presenting them as proven work.
- Review the About, Skills, Journey, Certificates, Store, and Contact pages for
  unsupported or unnecessarily sensitive statements.
- Add tested browser flows and screenshots from actual running builds.
- Keep a small curated portfolio instead of filling pages with placeholders.
